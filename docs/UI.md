# 设置页（UI）

设置页是 dsh-memory 的图形界面，入口在 **DSH 设置 → dsh-memory**。五个标签页从左到右：**配置 / 概览 / 浏览 / 审批 / 维护**，打开面板默认落在第一个「配置」——日常只用到它。

界面中英双语，默认跟随 DSH 的界面语言（`ui.lang: "auto"`）。所有写操作都走宿主 service，不直接改文件；能点的地方都写清楚"点完会发生什么"，危险操作需要二次确认。

## 配置

**首页就是它。** 页面分两块：最上面是记忆库路径，下面按三组排配置项——「先改这几项」→「常用」→「进阶」，和 [CONFIG.md](CONFIG.md) 的顺序一致，不用跳文档找。

| 区块 | 能做什么 | 说明 |
|---|---|---|
| **记忆库路径** | 显示当前 `<root>`；按钮：**选择目录** / **打开目录** | 路径只读展示，不提供输入框——避免手打路径出错 |
| **先改这几项** | `extractor.enabled`、`apiKey`、`baseURL`、`model`（`root` 见上一行） | 默认关抽取（零花费）；开抽取这四项缺一不发请求 |
| **常用** | `gate`、`hits`、`hitsChars`、`sessionInjects`、`sessionInjectWindow` | 控制"注入多少"，不确定就保持默认 |
| **进阶** | `link.similarMin`、`link.sameFactCos`、`decay.auto`/`tauDays`/`archiveDays`、`abstract.auto`、`replay.auto`、`budget.monthlyYuan` | 改之前先看 CONFIG.md 对应那句说明；没列在页面上的键手改文件 |

每项 label 后面有一个 **ⓘ**：鼠标悬停显示一句中文说明，和 CONFIG.md 表里那句话同源（也来自 service 的配置描述），不用来回切文档。

改完点**保存**，页面提示**需要重启 DSH 才生效**；不用自己猜是否已应用。

## 概览

一眼看库的健康度，不含任何可写操作：

| 指标 | 含义 |
|---|---|
| 活跃 / 总计 | 当前可用事实数与库内总行数（含已归档、已软删） |
| 向量 | 已生成向量的条数；长期明显低于活跃数，说明模型没在工作 |
| 关联 | 关联图边数；为 0 通常是 `link.enabled` 被关或向量缺失 |
| 待审 | 抽取/重放产生的候选，等你在「审批」页处理 |
| 回收站 | 软删待清理的条数（30 天后自动清理） |

数据来自 service 的 `stats`，与 `memory_health` 同源；两边对不上时以 `memory_health` 为准。

## 浏览

按 `value / subject / predicate` 搜索，按状态过滤（全部 / active / archived / deleted），分页展示。

- 每条可以**软删**（进回收站，可恢复）或**恢复**（对已删/已归档的条目）。
- 只能改状态，**不能改事实原文**——这是刻意的：真源在 Markdown 文件里，界面不做内容编辑。
- 搜索结果为空是正常结果，不会"凑"几条给你。

## 审批

处理抽取和重放送来的候选：**通过**或**驳回**（可填原因）。

- 通过 = 写成正式事实；驳回 = 丢弃，不留残渣。
- 重放上报的"疑点"会被标记为不可直接采信，通过时会被拒绝——避免把模型的猜测固化成事实。
- 队列里没有东西时是空列表，不是报错。

## 维护

四个动作，前三个需要**二次确认**；最后一个是备份：

| 动作 | 作用 | 风险 |
|---|---|---|
| **重建索引** | 从 Markdown 真源与库重建检索索引 | 只读真源，不删事实；耗时取决于库大小 |
| **执行遗忘扫描** | 立刻跑一次降权/归档判定（平时启动后自动跑） | 只降权与归档，不硬删；可恢复 |
| **清理回收站** | 物理删除 30 天前的软删条目 | **不可恢复**，确认后再点 |
| **导出** | 备份用：弹系统「另存为」，把活跃事实写成 JSONL | 只读操作，不改库；导出文件不含密钥 |
| 查看结果 | 每个动作返回条数与耗时；导出会回报条数与落盘路径 | — |

## 三个按钮的行为

| 按钮 | 在哪 | 打开什么 | 选完之后 |
|---|---|---|---|
| **选择目录** | 配置 tab · 记忆库路径 | 系统原生的文件夹选择框（Windows 资源管理器 / macOS Finder） | 路径回填到页面并保存；**下次启动**使用新目录。旧目录的数据不会自动搬，需要迁移时按 [TROUBLESHOOTING](TROUBLESHOOTING.md#windows-paths) 手工复制 |
| **打开目录** | 配置 tab · 记忆库路径 | 系统文件管理器，直接定位到当前 `<root>` | 只读用途：看 `global/facts/`、`exports`。不改任何东西 |
| **导出** | 维护 tab | 系统原生的「另存为」对话框 | 写出 `memory-<时间>.jsonl`，一行一条活跃事实，字段为 id/subject/predicate/value/tags/status 等；**不含 API key、不含向量与索引** |

要点：三个按钮全部走系统对话框，**页面里没有让用户手打绝对路径的输入框**。导出的默认建议位置是 `<root>/exports/`，你可以另选。记忆库路径只在「配置」tab，导出只在「维护」tab——分开是有意的：改路径是低频高风险，导出是低频只读。

## 斜杠命令（不开设置页也能用）

| 命令 | 等价操作 |
|---|---|
| `/memory` | 查看库概况 |
| `/memory-search <词>` | 搜索事实 |
| `/memory-rebuild [模式]` | 重建索引（可选 vec / link / decay / archive / tombstone / all） |
| `/memory-export [路径]` | 导出活跃事实为 JSONL，默认落在 `<root>/exports/` |

命令与面板改的是同一份数据，不需要二选一。

## 手改配置仍然有效

面板只暴露 18 个最常动的键（3 组），其余键——`link.maxOut`、`expandChars`、`decay.subjectOverrides`、`decay.maxPerCluster`、`abstract.llm.*`、`replay.perRun` 等——仍写在 `<root>/config.json`，见 [CONFIG.md](CONFIG.md)。

两边同时改时以文件为准：面板保存前会读回文件再合并，只覆盖你在页面上动过的键，不会把你手改的其它键清掉。保存后若提示需要重启，就重启。

## 排错

面板打不开、显示 0、或按钮没反应：先看 [TROUBLESHOOTING](TROUBLESHOOTING.md)，再确认 `memory.log` 里有没有 service 注册失败的行。
